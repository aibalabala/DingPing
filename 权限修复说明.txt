定屏 v0.5.6（构建 13）· 安装与授权

遇到「只有旧版 / 开关已开仍未授权」，优先使用 DMG 中的「双击安装预编译版.command」。
安装器会请求旧版退出，替换个人 Applications 中的旧版，将系统 Applications 中经核对的旧副本移到废纸篓，然后引导授权。保留布局配置。
从源码编译时用「双击修复升级.command」，它会串行执行安装确认和权限修复。
若旧版无法退出或移除，按终端提示处理后重试；安装阶段失败就不会继续重置授权。

授权的对象始终为：
个人文件夹/Applications/定屏.app
例如：/Users/mac/Applications/定屏.app

辅助功能列表里仍然只叫「定屏」，名称不能证明是哪个版本或哪个副本。
按照修复工具提示移除定屏的旧条目，再点 +，按 Command + Shift + G，
输入个人 Applications 文件夹路径，选中其中的定屏.app，打开开关，然后回到终端按回车启动。
如果界面没刷新，先切换到其他系统设置页面，再回到辅助功能。

修复工具不会自动给自己授权。最后以正在运行的定屏「权限诊断」为准：
版本 0.5.6（构建 13） / 当前应用完整路径 / 辅助功能检测：已授权。
脚本显示「签名校验通过」不代表已经获得辅助功能授权。

如果你确定已经装好当前版本，也可以单独运行「双击修复定屏权限.command」。
它只接受与本包版本、构建号、内容指纹及签名相符的安装。
遇到旧版、未知副本或仍在运行的进程会停止，不会重置其授权。

修复仅使用 macOS 的 tccutil，限定 local.dingping.fixedsplit 的 Accessibility。
不会全局重置权限，不修改 TCC 数据库，不禁用系统保护，不使用 sudo，
不改动其他路径的同名 App。独立授权修复工具不会自动关闭程序；升级安装器会先请求正在运行的定屏退出。

目前 App 使用临时签名，没有稳定的 Developer ID 签名。DMG 自带「双击修复定屏授权.command」，不必下载源码包即可引导修复。
安装器避免同一安装反复被重新签名；更换应用构建后仍可能需要重新授权。
不能保证今后所有升级都自动沿用旧授权。

日志位于个人文件夹/Library/Logs/定屏：
DMG安装日志.txt / DMG授权修复日志.txt / 升级修复日志.txt / 安装日志.txt / 权限修复日志.txt / 已安装版本.txt。
如果仍失败，请提供「权限诊断」复制内容和升级修复日志中的失败部分。
