# v0.6.0 检查记录

本地制作环境为 Linux / GCC / Bash，没有 macOS SDK、AppKit 或用户机器的辅助功能权限。原生应用构建与安装包校验由 GitHub Actions 的 macOS ARM64 runner 执行；运行状态以仓库 Actions 页面为准。真实 macOS 26 窗口操作仍需在用户机器验收。

## v0.5.9 实机输入

用户诊断显示辅助功能已授权、目标屏可调整窗口 9 个，三个分区中 Chrome 和 Code 的固定记录未找到窗口，只有终端已到位。拖动记录表明鼠标下找到了屏幕窗口，但 AX 匹配失败。因此固定目标恢复和拖动起点识别需要分别处理。

## 本版实现与边界

- 将固定目标和分区当前占位分开。匹配优先级：当前运行的 AX 窗口身份、唯一文档、唯一标题、该应用唯一的普通窗口。多窗口无法区分时不认领固定目标；空格允许临时补位，目标回来后优先收回。固定记录不会被临时窗口改写。
- 分区归属变化时清除旧窗口的延迟移动校验，避免新窗口被旧请求标记为暂停。布局方案切换只缓存真实固定目标的运行时身份，不缓存临时占位。
- 拖动起点以鼠标位置的 AX 命中为优先证据，同时要求与最前方 CG 窗口的进程一致。其他情况需与前方窗口有明确几何重合；AX 与 CG 边界不同且鼠标处于 AX 顶部时，用 AX 框作为标题栏起点。诊断输出失配的 PID 与 AX 命中结果。
- 不更改安装位置或配置版本；继续使用 layouts.json 版本 2，给固定目标增加可选文档字段。旧配置直接读取。

## 已运行的检查

- 十种布局：113,281 条几何断言；自动放置穷举与新窗口策略通过。
- 新的固定目标分配测试覆盖两格固定目标缺席且第三格为终端、临时补位、目标回来收回、标题变化、同应用多窗口歧义与运行时身份优先。
- 拖动测试覆盖 CG 边界不一致时的直接 AX 命中和重合匹配、标题栏位置、窗口回弹、落点、交换和固定目标保护。
- 27 项安装策略与失败回滚模拟通过；中文 Shell 提示在 CURRENT、C、C.utf8 下通过；所有 Shell 脚本通过 `bash -n`；`git diff --check` 通过。

这些检查不能证明 Chrome、Code 或其他应用在用户的 macOS 26 上实际接受调整。请按 [MAC_ACCEPTANCE.md](MAC_ACCEPTANCE.md) 验证三格自动填充、固定目标回来收回及拖动换位。
