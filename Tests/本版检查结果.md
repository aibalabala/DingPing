# v0.7.1 检查记录

本地环境为 Linux / GCC / Bash。原生 arm64 应用、Foundation 持久化测试、图形安装包和 DMG 由 GitHub Actions 的 macOS runner 构建与检查；真实 macOS 26 拖放行为需实机验证。

## 用户已确认的 v0.7.0 行为

- 右侧上下窗口交换成功，说明本次场景的拖动识别与松手提交可执行。
- 左右失败的诊断明确为“目标分区或来源窗口已固定，未换位”。左侧 Chrome 是唯一固定目标，右侧 Chrome 和访达未固定；现有固定规则能够解释方向不同的结果。这份诊断没有显示横向坐标计算失败。

## 本版修改

- 已分配窗口之间的主动拖放允许交换在位固定窗口。窗口、固定目标和临时补位身份一起交换，固定位置保存为新分区。
- 两格都有固定目标，或其中一个目标暂缺时，保留并交换两份固定记录，不覆盖或丢弃任一目标。
- 自动激活新窗口仍使用原有固定分区保留规则。未知来源窗口不能直接替换在位固定目标；隐藏固定目标不参与当前布局交换。
- 分区提示、设置页、帮助和诊断说明固定位置随手动换位更新。配置继续使用版本 3。

## 验证

- C 拖动规则测试加入用户三格真实坐标下的左到右、右到左、右侧上下判定及固定目标参与交换。
- 固定恢复测试加入两个不同 Chrome 窗口交换后重新扫描、重启解析；自动分配保留固定位置的穷举测试继续执行。
- Foundation 测试加入窗口与固定目标同步交换、反向交换、JSON 重启保存、暂缺 Code 目标保留。该测试在 macOS 原生构建流程执行。
- 安装版本统一为 0.7.1 / 构建 19，升级路径与原有方案保持兼容。
