# v0.7.0 检查记录

本地环境为 Linux / GCC / Bash，无法运行 AppKit 和真实辅助功能窗口。GitHub Actions 的 macOS ARM64 runner 负责编译、运行 Foundation 持久化测试及打包检查；该 runner 也不能替代用户 macOS 26 桌面的实际拖动验收。

## 来自用户的 v0.6.0 诊断

- 辅助功能已授权，三个分区找到窗口且坐标到位。拖动判定显示“被后续操作取消”。代码里松手后延迟 120 毫秒提交，而打开菜单调用了取消路径；这能直接解释诊断里的取消结果。
- 诊断只显示 Chrome 固定、两个终端可补位，Code 固定目标已不在当前方案。旧版把固定目标和占位共用一条记录，存在手动选窗覆盖的路径；诊断本身不能确定 Code 具体在哪一步丢失。
- v0.6.0 把 runner 编译通过误写成实机可用的结论。这不是有效的 macOS 26 拖放验证。

## 结构修改

- 配置版本 3 用 `pins[4]` 保存固定目标，用 `bindings[4]` 保存最近占位。自动归位、空格补位、换位和重扫只更新占位。版本 1/2 升级前保存原始配置到 `layouts-before-0.7.0.json`。已在旧配置中消失的固定目标需要用户重新固定。
- 松手后的拖放交易有独立的 pending token；菜单取消前置操作不会取消该交易。权限诊断等待松手交易完成再读取结论。桌面、模式或显示器确实改变时仍取消。
- 固定目标缺席的格子保留当前临时占位窗口，避免手动换位后解析器立刻换回其他窗口；固定目标出现则优先收回。
- 选择另一窗口替换固定目标会显示确认，取消后原目标保留。

## 自动检查与剩余验证

- 本地 C 规则测试覆盖拖放判定、延迟 token、固定目标缺席时换位后重扫、固定目标返回；27 项安装策略与回滚模拟通过，Shell 语法和差异空白检查通过。
- macOS Foundation 的配置迁移、自动占位隔离、JSON 重启持久化测试在原生构建脚本中运行，结果以对应 GitHub Actions 构建记录为准。
- 尚未完成真实 macOS 26 上的 Chrome、Code、两个终端窗口拖放、菜单立即打开及升级授权验收。请按 [MAC_ACCEPTANCE.md](MAC_ACCEPTANCE.md) 的场景记录操作与诊断。
